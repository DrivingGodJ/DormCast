# 物理设备验收与延迟测量

本页提供可复现方法，不把网络 RTT 当作音频延迟。

## 一次测量需要记录什么

| 字段 | 记录内容 |
|---|---|
| 主机 | Windows 版本、CPU、默认输出设备、软件版本、10/20ms 帧长 |
| 网络 | 路由器、2.4/5/6GHz、信号强度、是否隔离/漫游、连接人数 |
| 接收端 | 型号、操作系统、浏览器版本、目标缓冲、扬声器/有线/蓝牙 |
| 数据 | 声音端到端延迟 p50/p95/max、设备间偏差 p50/p95/max、卡顿数 |
| 遥测 | 导出主机诊断，包含 RTT、抖动、缓冲、丢包和主机丢弃统计 |

## 声学测量

1. 主机播放带清晰间隔的短脉冲/点击音。这个文件只是测试刺激，广播仍从真实 WASAPI 系统回环捕获。
2. 同一录音设备以至少 48kHz 录下主机扬声器和一个接收扬声器。分别放在靠近左右麦克风的位置，使用双声道录音隔离声源；不要用两个独立录音设备的系统时间相减。
3. 对每次脉冲做互相关，得到同一录音时钟下两条音轨的时间差。校正声源到麦克风距离：每米约 2.9ms。用至少 30 次脉冲统计分位数，不只测第一次。
4. 多设备偏差：同一录音设备同时录下两台接收端，比较同一源脉冲的到达时刻。主机→A 和主机→B 两次不同环境的测量不能直接声称是同时的 A/B 偏差。
5. 更精确的电气方法使用多通道音频接口同时采集主机和各客户端的模拟输出，排除空气传播；必须对齐同一采样时钟。

屏幕上点击播放到听见声音的秒表、WebSocket ping/2、WebRTC jitterBufferDelay 和视频帧数估计都不能替代上述声学/电气测量。Web Audio `outputLatency` 也是系统估计，不包含所有硬件路径。

## 验收矩阵

每组至少连续播放 10 分钟，记录 30 次脉冲；正式稳定性验收再运行 2 小时。

| 用例 | 操作与验收 |
|---|---|
| 1 台 | 检查音质、左右声道、p50/p95 延迟、无持续增长 |
| 2 台 | 同时测实际输出偏差；手动调节较快设备缓冲，记录调节前后 |
| 5 台 | 同时播放，检查主机 CPU/内存/上行、各端丢包、最大偏差 |
| 不同信号 | 同一组设备分别靠近 AP、隔墙、弱信号测量，不改变其他变量 |
| 中途加入/退出 | 加入听到当下片段；一个退出不使其他设备断开 |
| 切歌/暂停/继续 | 从实际音乐软件操作主机，接收端跟随；恢复后不复播暂停前缓存 |
| 断网恢复 | 听众断开 Wi-Fi 5 秒后恢复；自动重连到实时位置，必要时允许移动浏览器再次点击收听 |
| 主机换网 | 地址失效时停止旧广播，换网卡重新开始，固定 .local 名称重新发布；IP 备用链接会变化 |
| 音频设备 | 默认扬声器→有线/USB 设备→拔出；检查重连和无旧声音复播 |
| 托盘 | 开始后关闭窗口，服务仍在；托盘左键恢复、右键停止/退出 |
| 彻底退出 | 退出后 EXE 进程消失、TCP/UDP 套接字消失；同端口可以再次启动 |
| 无互联网 | 路由器断开外网但保留 LAN，确认加入、音频和重连仍工作 |
| 不支持策略 | 测试 iOS 锁屏/后台、Android 省电、Safari/Firefox HTTP WebRTC 和自动播放 |

主机同步模式下，本机网页会作为静音预览，避免系统回环再次捕获接收声音形成回授；真实接收测试使用其他设备。非主机同步模式的本机自动化测试需在测试工具内静音媒体元素。
